## Problem

SelectContent unconditionally applies the `dark` class, so light-theme pages open a dark popover.

## Evidence

Unmodified preview, light document class; Transport popover computed background oklch(0.228 0.013 107.4) and popup class begins `dark`. See `select-light-theme.png`.

Source paths are relative to repository root. Line numbers refer to source revision 127dd90e0428ea0d90dfd77e48712e639d386d15; the two pre-existing firmware edits do not affect this evidence.

## Impact and severity rationale

Low: theme inconsistency affects transport and every shared select consumer.

## Root cause

The reusable popup hard-codes a theme override instead of inheriting the active theme.

## Proposed resolution

Use active semantic theme tokens across portals and document intentional theme exceptions explicitly.

## Implementation record

None. Audit and planning only; no product code changed.

## Verification and regression evidence

Baseline evidence supports the finding, not its closure. Open transport, log filters, rangefinder and stepper selectors in both themes. Check popup foreground/background/focus/selected states.
