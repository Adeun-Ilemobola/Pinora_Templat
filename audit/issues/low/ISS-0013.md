# ISS-0013 — Sidebar collapse preference is written but never restored

- Severity: Low
- Status: Open
- Confidence: Confirmed
- Category: UI / usability / presentation
- First observed: 2026-11-05
- Last updated: 2026-11-05
- Location: UI/src/components/ui/sidebar.tsx:28,57-86; UI/src/components/AppLayout.tsx:36
- Related requirements: REQ-0003
- Related / blocking issues: See the canonical register and assigned phase; no implementation dependency on the historical PIN-TPL audit.
- Assigned phase: UI Phase 2

## Problem

SidebarProvider writes sidebar_state to a cookie, but initializes from defaultOpen=true and never reads the saved preference. Reload re-expands it.

## Evidence

Browser at 800×600: after Toggle Sidebar, data-state was collapsed; after reload it was expanded. The source confirms no preference read.

Source paths are relative to repository root. Line numbers refer to source revision 127dd90e0428ea0d90dfd77e48712e639d386d15; the two pre-existing firmware edits do not affect this evidence.

## Impact and severity rationale

Low: compact-window users must repeatedly recover their chosen workspace width.

## Root cause

Persistence is implemented only on the write path.

## Proposed resolution

Choose and document one supported desktop/browser preference store, restore valid state on startup, and keep mobile overlay state separate.

## Implementation record

None. Audit and planning only; no product code changed.

## Verification and regression evidence

Baseline evidence supports the finding, not its closure. Collapse/reload and expand/reload both restore correctly; invalid preference has a safe fallback; mobile overlay behavior and keyboard shortcut remain usable.

## History and closure

2026-11-05: Created Open. Observed in source and/or the explicitly described browser fixture. No repair or verification sign-off.
