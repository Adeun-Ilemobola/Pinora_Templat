# ISS-0010 — System theme support does not track preference changes

- Severity: Low
- Status: Open

## Problem

ThemeProvider supports the value system but samples matchMedia only when theme changes. It never subscribes to preference changes. The shell toggle also chooses an icon/action from the stored value rather than a resolved system theme.

## Evidence

Complete ThemeProvider and AppLayout inspected. No OS appearance setting was changed; this is source-confirmed missing subscription. Normal dark/light toggle was visually checked.

Source paths are relative to repository root. Line numbers refer to source revision 127dd90e0428ea0d90dfd77e48712e639d386d15; the two pre-existing firmware edits do not affect this evidence.

## Impact and severity rationale

Low: users with system mode saved can see a stale theme and a misleading next action. The current shell exposes only a two-way toggle, which limits reachability.

## Root cause

Stored theme preference and resolved visual theme are not modeled separately.

## Proposed resolution

Validate saved preference, track resolved theme, add a matchMedia change listener while system mode is active, and use resolved theme for toggle copy/icon.

## Implementation record

None. Audit and planning only; no product code changed.

## Verification and regression evidence

Baseline evidence supports the finding, not its closure. Mock matchMedia changes and legacy/invalid stored values; verify active theme, toggle label, listener cleanup and persistence.
