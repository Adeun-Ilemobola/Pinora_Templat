## Problem

At the configured 800×600 viewport, a 256px expanded sidebar remains visible, transport/statistics stack vertically, and module work is below the first screen. At wide sizes an empty statistics card stretches to match transport.

## Evidence

Browser measurements at 800×600: transport top 168px, height 397px; statistics top 589px, height 288px; module empty card top 945px. The transport height includes the browser-only missing-IPC error, so exact native height will differ. At 1440×900 both overview cards measured 397px tall. See dashboard screenshots.

Source paths are relative to repository root. Line numbers refer to source revision 127dd90e0428ea0d90dfd77e48712e639d386d15; the two pre-existing firmware edits do not affect this evidence.

## Impact and severity rationale

Medium: the default desktop size emphasizes setup and empty space over the controls users opened the app to use. No horizontal overflow was observed in this measured state.

## Root cause

Viewport breakpoints are used without accounting for sidebar width; connection configuration and overview details occupy the main dashboard hierarchy.

## Proposed resolution

Make the shell respond to available content width; show a compact connection summary after connection, disclose configuration/details, and use content-sized overview and module cards. Keep 800×600 supported before considering a larger default window.

## Implementation record

None. Audit and planning only; no product code changed.

## Verification and regression evidence

Baseline evidence supports the finding, not its closure. Compare disconnected and synthetic connected states at 800×600, 1024×768, 1440×900, and narrow fallback. Verify connect/disconnect and the first useful module action are easy to find without excessive setup scrolling.
