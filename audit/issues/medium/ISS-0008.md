## Problem

The five existing frontend suites cover state/protocol/auth/log helpers but do not mount views or exercise layout, accessible naming, focus, navigation, and pointer/keyboard workflows.

## Evidence

All five test files and their test declarations were inspected. Baseline: 173 passed, 0 failed. The temporary synthetic preview is an evidence harness, not a permanent component or end-to-end test suite.

Source paths are relative to repository root. Line numbers refer to source revision 127dd90e0428ea0d90dfd77e48712e639d386d15; the two pre-existing firmware edits do not affect this evidence.

## Impact and severity rationale

Medium: layout and interaction changes can regress while all existing checks stay green.

## Root cause

Prior modernization prioritized protocol and store correctness rather than rendered UI coverage.

## Proposed resolution

Add a small durable fixture-backed component/browser suite during the UI phases; promote meaningful regressions as each fix lands, then enforce the cross-page matrix in Phase 5.

## Implementation record

None. Audit and planning only; no product code changed.

## Verification and regression evidence

Baseline evidence supports the finding, not its closure. Check failures are caught for read-only eligibility, missing LiDAR children, named slider, log identity, theme portals, and default-size layout. Run existing suites unchanged and test native WebView behavior separately.
