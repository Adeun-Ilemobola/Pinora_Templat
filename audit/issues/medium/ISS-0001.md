## Problem

Helper copy and metric labels use the same muted foreground on white/light surfaces. The opaque token pair measures 4.260:1 on white and 3.862:1 on the muted surface.

## Evidence

The unmodified light-theme preview renders these tokens. `test/runs/ui-audit-2026-11-05/measure-contrast.py` converts the actual OKLCH tokens to linear sRGB and calculates relative luminance; see `contrast-results.json` and `dashboard-light-800x600.png`.

Source paths are relative to repository root. Line numbers refer to source revision 127dd90e0428ea0d90dfd77e48712e639d386d15; the two pre-existing firmware edits do not affect this evidence.

## Impact and severity rationale

Medium: repeated small labels and instructions become harder to read. This finding concerns active text, not disabled control text.

## Root cause

The light muted foreground token is too light for normal text on its intended surfaces.

## Proposed resolution

Adjust semantic foreground tokens and check all active text/surface pairs in both themes; retain quieter hierarchy using size/weight/spacing as well as color.

## Implementation record

None. Audit and planning only; no product code changed.

## Verification and regression evidence

Baseline evidence supports the finding, not its closure. Rerun the contrast script against revised tokens; verify active normal text reaches 4.5:1, inspect actual composed backgrounds, and capture light/dark reference states. This is a sampled contrast check, not whole-app WCAG certification.
